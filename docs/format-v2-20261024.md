# Snapshot format 2 - 2026-10-24

Unreleased work in `main`; the published module is still 0.2.0. Format reference:
[snapshot-format.md](snapshot-format.md).

## Why

Format 1 stored each object as an array of decimal byte values. That costs up to
four characters per byte and, for every mebibyte of content, a JSON array of a
million numbers in both directions: the request from the adapter and the
snapshot written to disk. On the reference host a 1 MiB backup took 2396 ms for
a tree that a filesystem copy does in milliseconds.

Base64 costs four characters per three bytes and keeps the payload as text, so
`JSON.parse`/`stringify` and `Buffer.from` do the work in native code.

## Measurements

Reference host: V100 server, Ubuntu 22.04, gcc 12.3, Node 20.20.2, moon
0.1.20261023, debug builds, `/tmp` on local disk.

| Workload | Format 1 | Format 2 |
|---|---:|---:|
| 1 MiB incompressible, snapshot size | 3.57 MiB | 1.33 MiB |
| 1 MiB incompressible, backup | 2396 ms | 649 ms |
| 1 MiB incompressible, restore | 2081 ms | 423 ms |
| 2 MiB incompressible | n/a (1 MiB cap) | 971 ms / 671 ms, 2.7 MiB |
| 4 MiB incompressible | n/a | 1877 ms / 1107 ms, 5.3 MiB |
| 8 MiB incompressible | n/a | 3325 ms / 2047 ms, 10.7 MiB |
| 50 text files, 76 KiB | - | 174 ms, 1.46x |

The adapter ceiling moves from 1 MiB to 8 MiB of source bytes for the same
16 MiB request budget: 8 MiB of incompressible data becomes 10.7 MiB of base64
JSON. `SNAPVAULT_ADAPTER_LIMIT_BYTES` raises or lowers it.

## Compatibility

- `"format": 1` reproduces the old layout byte for byte, checksum included.
- Reading is version-directed: a decimal payload in a format 2 snapshot is
  `invalid object encoding`, and a base64 string in a format 1 snapshot fails the
  same check.
- `audit` reports `format`; `restore` reports `format` and `encoding` and keeps
  the payload in the encoding it validated.
- `retention` plans across formats and counts decoded bytes, so its totals do not
  drift with the encoding.

## Not changed

Snapshots are still self contained, so `new_object_bytes` remains a content
statistic; `retention` still only plans; regular files only; manifests are
integrity checked, not authenticated. Base64 is not compression - a 1 MiB file
still costs 1.33 MiB on disk, and incompressible data is not shrunk, only
encoded more compactly than before.
