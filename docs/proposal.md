# Moon SnapVault 项目申报书

项目负责人账号：yyqdbngt。项目方向：文件工具与数据完整性。
GitHub：https://github.com/yyqdbngt/moon-snapvault公开仓库，拟用 `yyqdbngt/moon-snapvault`。
当前阶段：选题与架构规划；本文按立项阶段表述功能、交付和验收目标。

## 项目简介与通用价值

可靠地创建本地增量快照，证明恢复结果和备份内容一致。项目采用 MoonBit 实现核心处理能力，提供可复用库接口与命令行入口，使使用者能够把同一能力嵌入应用、离线处理或 CI 流程。适用范围通过不同用途的完整示例说明，并以输入、判断过程和可核验输出体现实际价值。

## 核心功能

文件扫描与规则；版本化清单；摘要与内容寻址；增量差异；快照提交；恢复计划及执行；完整性校验；中断恢复与 CLI。十月先采用文件级去重，暂不增加分块算法、压缩和远端存储。

## 三个完整使用场景

1. 项目误删恢复：对测试源码目录创建两个版本快照，再模拟修改和删除；根据差异选择恢复版本，在独立目录恢复并逐文件比较路径与摘要，输出恢复验证报告。

2. 数据交付核验：对交付目录生成版本化清单，模拟接收端缺文件或内容变化；输出遗漏、增加和摘要不一致项，让交付双方能够定位不完整数据。

3. 归档迁移验证：输入多层目录和重复内容文件，创建去重快照并迁移到独立存储目录；恢复后比较全量结果，输出对象复用与完整性统计，证明备份能够实际还原。

## 技术路线与工程实现

以内容摘要定位文件对象，版本化清单保存文件路径和元数据；快照写入分为准备与提交阶段，恢复根据明确计划执行并进行逐文件核验。核心逻辑采用有类型的数据结构、明确错误结果和可测试执行步骤；文件、网络或进程适配与核心处理分层。实现过程中用小规模确定性输入建立正确性基准，再使用真实场景和规模数据检查可用性。对外暴露稳定接口，避免把演示脚本作为唯一使用方式。

## 预计交付与验收方式

交付目标包括公开 MoonBit 源码、库接口、CLI、三个完整场景及输入来源、单元与集成测试、适用目标的 CI、安装使用说明、设计与边界文档、源码统计及独立安装验证记录。有效生产 MoonBit 源码内部估算为 5,000–8,000 行，测试、示例、生成语料和辅助脚本分别统计，该估算不作为官方验收门槛。

一千文件/约定容量数据的新增、修改、删除、重复内容均有明确预期；完整恢复后路径集合与摘要和源版本相同。失败验证覆盖坏清单、丢失对象、恢复中断、越界路径和符号链接策略。恢复操作验证绝对目标在指定目录内。十月为本地备份工具，不宣称分布式一致性或加密存储。
